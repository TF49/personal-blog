# 涂家乐个人博客 · 视觉与交互设计规范

- 版本：v2.3
- 状态：视觉基线与首页内容结构已确认，下一阶段进入内容质量
- 更新日期：2026-11-11
- 适用范围：personal-blog 全站前端
- 设计方向：Max Milkin 主导的原创技术博客

> 本文是当前唯一设计依据。旧版任务记录、阶段验收、偏差说明和会话入口已全部移除。

## 1. 设计决策

### 1.1 不做 1:1 复刻

本站不复制 Max Milkin 的文案、Logo、照片、字体文件、3D 模型、源码或精确页面结构。

Max Milkin 是创意开发者作品集，目标是展示视觉能力和项目案例；涂家乐是工程师的技术博客，目标是让读者快速发现、阅读和回访内容。两者可以共享视觉纪律，但不能共享同一套产品结构。

### 1.2 不做平均拼接

本站采用有主次的融合，而不是把多个网站的组件等量拼在一起：

| 层级 | 来源 | 负责内容 |
|---|---|---|
| 主视觉语言 | Max Milkin | 色彩、留白、分区编号、幽灵标题、滚动节奏、克制动效 |
| 内容索引 | Josué Pichot（https://jozue.fr/） | 文字型文章索引、标签药丸、筛选方式 |
| 关于页结构 | Sean Currlin（https://seancurrlin.com/） | 居中窄栏时间线、阶段化经历 |
| 技术启发 | Codrops 案例（https://tympanus.net/codrops/2025/12/02/two-portfolios-one-process-where-design-motion-and-code-come-together/） | GSAP、字母聚拢和滚动编排的思路 |

Decart 仅作为早期信息架构对照，不进入当前设计系统。

### 1.3 视觉比例

- Max 视觉语法：70%–80%
- Josué 内容索引：15%–20%
- Sean 时间线：5%–10%
- 涂家乐原创内容、中文排版和博客交互：必须占主导

如果某个参考元素不能服务技术博客的阅读任务，则不采用。

## 2. 产品定位

### 2.1 一句话定位

> 一个安静、克制、具有动态张力的工程师技术博客。

### 2.2 体验关键词

安静、准确、留白、工程感、持续阅读、轻量动效、中文优先。

### 2.3 设计目标

1. 首屏建立清晰的个人识别和技术气质。
2. 通过滚动和字母动效形成记忆点，但不干扰阅读。
3. 文章列表让标题、分类、日期和摘要一眼可扫。
4. 文章详情页优先保证长文可读性、代码可读性和链接可用性。
5. 所有视觉效果在移动端、低性能设备和减少动态效果模式下保持完整内容。

### 2.4 非目标

- 不复制 Max 的页面、文案、素材和精确动效。
- 不把博客做成作品集卡片墙。
- 不引入深色/浅色主题切换。
- 不新增后端、评论系统、搜索服务或 CMS。
- 不为了视觉效果牺牲文章正文的可读性。
- 当前阶段不继续引入新的参考网站、颜色体系或无关视觉模块。

## 3. 设计系统

### 3.1 色彩

全站只使用两个主色和它们的同色混合：

| 令牌 | 值 | 用途 |
|---|---|---|
| sage | #C2CABB | 主背景、联系区、时间线区 |
| ink | #10120F | 主背景、文章列表、关于区 |
| on-sage | ink | sage 背景上的正文 |
| on-ink | sage | ink 背景上的正文 |
| fg-muted | 当前前景色的约 70% | 次要信息 |
| line | 当前前景色的 24%–28% | 分隔线 |
| ghost | 当前背景上约 4%–8% 的同色混合 | 装饰性大字、代码背景 |

颜色必须使用 CSS 语义变量，不在组件内新增蓝色、紫色或渐变强调色。

### 3.2 字体

- 拉丁文：Inter Tight Variable
- 中文：Noto Sans SC Variable
- 代码：JetBrains Mono

中文不强行套用拉丁文的大写、紧字距和超窄字形。中文标题以字面节奏、行宽和留白建立层级。

### 3.3 字号

| 角色 | 桌面 | 移动端 | 说明 |
|---|---:|---:|---|
| 装饰性 display | 160px | 72px | 只用于幽灵标题，不承载正文信息 |
| 页面 h1 | 56px | 36px | 页面主标题 |
| 区块 h2 | 32px | 24px | 区块标题 |
| 文章正文 | 17px | 17px | 行高 1.85 |
| 普通说明 | 15px | 15px | 行高 1.7 |
| 标签与导航 | 13px | 13px | 适度字距，最小触控区域 44px |

### 3.4 网格与间距

- 内容最大宽度：1230px
- 视口两侧 gutter：clamp(20px, 7.3vw, 105px)
- 正文最大宽度：720px
- 时间线最大宽度：670px
- 基础间距：4px
- 常用间距：8 / 16 / 24 / 32 / 48 / 96px
- 图片圆角：4px
- 药丸圆角：999px
- 其他容器默认不加圆角

页面必须保持大块留白和硬切换的色调分区，不使用渐变来掩盖布局问题。

## 4. 信息架构

保持四条路由：

| 路由 | 任务 | 视觉策略 |
|---|---|---|
| / | 认识作者、感受气质、进入文章 | Max 主导 |
| /blog | 浏览、筛选和选择文章 | Max + Josué |
| /blog/:slug | 安静阅读一篇文章 | 原创阅读系统 |
| /about | 了解经历、技术栈和项目 | Max + Sean |

全站共享固定顶部导航、页面切换、Lenis 平滑滚动和页脚。

## 5. 页面设计

### 5.1 首页

首页不是功能面板，而是一段有节奏的个人介绍。

首页以 Max 的七段节奏为骨架（v2.2），v2.3 扩展为十段，每一段都用本站真实数据回答一个问题：作者是谁、在想什么、做过多少、走过哪些阶段、正在写什么、做过什么、会什么、这个网站如何运作、常见疑问、怎么联系。新增分区只允许使用站点内可核对的数据（文章、精选仓库、技术栈、时间线），不写虚构统计、奖项或客户。

顺序与编号（色调对应 Max：首屏 sage → 关于 ink → 记录 sage → 作品/能力 ink → 表单/页脚 sage）：

| 编号 | 分区 | 色调 | 对应 Max 分区 |
|---|---|---|---|
| — | 可跳过的入口加载层 | — | Loader |
| N.001 | HOME 首屏 + 宣言段 | sage | Hero（含钉住的宣言） |
| N.002 | ABOUT 关于（含当前关注） | ink | About |
| N.003 | RECORD 记录 | sage | Awards |
| N.004 | PATH 历程 | sage | —（v2.3 新增，承接 RECORD 的阶段数） |
| N.005 | WRITING 最新文章 | ink | — |
| N.006 | PROJECTS 开源项目 | ink | Works |
| N.007 | STACK 技术栈 | ink | Expertise |
| N.008 | COLOPHON 本站构建 | sage | —（v2.3 新增） |
| N.009 | Q&A 问答 | ink | —（v2.3 新增） |
| N.010 | CONTACT 写信 | sage | Contact form |
| — | 页脚 | sage | Footer |

#### 首屏

- 高度约 100svh，固定导航占用 64px。
- 左侧或中左区域放置一个原创 3D 主体或静态回退图。
- 右下区域放置中文主标题、个人身份和极短说明。
- 标签格式为（HOME.）与 [N.001]，分别位于左右锚点。
- 装饰性 TF49 或幽灵字只作为背景层，不与主标题争夺注意力。
- 3D 主体必须有可信的材质层次、光照和阴影；程序化模型只是技术方案，不是视觉完成标准。
- 移动端优先保证标题、身份和联系入口完整显示，主体可以缩小或静态化。

#### 关于区

- ink 背景。
- 使用幽灵大标题，但必须让真实中文标题和简介保持可读。
- 字母聚拢是记忆点，不是内容本身；动画结束后必须稳定显示完整文本。
- 桌面端加入头像或其他原创视觉锚点，使字母运动有落点。
- 增加明确的“关于我”入口，连接到 /about。
- 移动端退化为整段淡入，不使用飞行字母栅格。
- 简介之后加入“当前关注”文字索引，作为关于区的内容延伸，不新增独立色调分区。
- 幽灵大标题为 5 行错位排布（ENGINE / ERING / NOTES / FROM / TF49），按 Max 的断词节奏左缩进交错，滚动时奇偶行反向横移。
- 当前关注固定为三个可持续主题：完整系统、AI 工具链、工程写作；每项包含局部序号、英文短标签、中文标题和一句具体说明。
- 桌面端使用三列细分隔线索引，移动端改为连续单列；它是文字索引而不是卡片，不加独立底色、阴影或大圆角。
- 当前关注的文案必须能从作者简介、实际技术方向和博客内容中得到支持，不使用虚构数据或短期状态填充版面。

#### 最新文章

- 只显示最近 4–6 篇。
- 标题下方提供一段简短导读，说明文章侧重问题背景、方案取舍和工程复盘，不使用营销口号。
- 桌面端在索引上方显示当前实际加载的近期文章数量和“全部文章”入口；移动端只在列表之后保留入口，避免头部拥挤。
- 使用两列文字索引，不使用卡片墙。
- 每行包含编号、分类、标题、日期和摘要。
- hover/focus 时当前行保持清晰，其他行降至约 40% 透明度。
- 预览卡不得遮挡当前标题、日期或键盘焦点。
- 首页分区标签统一使用 WRITING；文章页使用 POSTS。
- [N.004] 必须与分区标题保持左右对齐。

#### 宣言段（首屏延伸）

- 与首屏同属一个 sage 分区，桌面用 CSS sticky 钉住一屏（约 150–170svh 滚动行程）。
- 主句逐字随滚动从 16% 点亮到正文色，按中文标点切成短语，短语内不断行；补充说明随后淡入。
- 顶部：N. + 年份数字滚轮、居中 +、右侧 notes 状态点；底部：所在地本地时间与 edition 版本号。
- reduced-motion 下不钉住，文字直接完整显示。

#### 记录区（RECORD）

- sage 背景，巨型数字滚轮（最大 620px，比底色略亮的同色相）作为装饰背景，随滚动滚到技术栈总数。
- 前景为左侧大标题 + 右侧短说明 + 居中计数行；计数全部由数据计算：文章总数、精选仓库数、技术栈条目数、时间线阶段数。

#### 历程（PATH）

- sage 背景，与 RECORD 之间用细线分隔；数据直接来自 `timeline.ts`，不新增文案。
- 关于页是竖排窄栏时间线，首页为避免重复改为横向五列条带：一条细线串起各阶段，每列为序号 / 阶段名、标题、一句说明。
- 桌面端随滚动从左向右画出进度线、节点依次从约 28% 点亮到正文色（GSAP scrub）；手机端与 reduced-motion 下为静态竖排列表。
- 标题区右侧提供“完整经历 →”入口，链接到 /about。

#### 开源项目（PROJECTS）

- ink 背景，桌面端一屏高，项目名按预设落点散布（左右交错、上下错开），标签（PROJECTS.）居中。
- 悬停/聚焦项目名时其余项目降至 30%，中央面板显示语言、说明与主题；未激活时显示仓库数量与操作提示。
- 手机端退化为单列文字索引，直接显示说明。
- 首次渲染使用本地精选仓库（无布局跳动），随后通过 `getPinnedRepos` 获取 GitHub 实时数据（含 30 分钟本地缓存）；底部标注数据来源 `LIVE · GitHub API` 或 `LOCAL · 本地精选数据`。
- 仅在实时数据下显示“最近推送 · N 天前”；本地兜底数据的时间是手写的，不展示。任何情况下都不显示星标数。

#### 技术栈（STACK）

- ink 背景，按方向分行的斜杠分隔词串，居中排布；第一行正文色，其余弱化色，悬停行提亮。

#### 本站构建（COLOPHON）

- sage 背景，五步文字流水线：WRITE（Issues）→ FETCH（generate-articles.mjs）→ DATA（articles.json）→ BUILD（tsc + Vite）→ DEPLOY（GitHub Pages）。每步含序号、英文键、中文标题、一句说明和对应的真实文件或命令。
- 底部一行列出主要依赖的实际安装版本与最近构建日期，均由 `vite.config.ts` 的 `define`（`__BUILD_INFO__`）在构建时注入，不手写；右侧“查看源码”链接到仓库。

#### 问答（Q&A）

- ink 背景，左栏标题（桌面端 sticky），右栏为原生 `details/summary` 折叠列表，不依赖脚本，键盘与读屏可用。
- 回答只写能被站点或仓库核对的事实：文章来源、当前在做的项目、评论数不是阅读数、勘误方式、联系方式；最后一问链接到写信区锚点 `#contact`。

#### 写信区（CONTACT）

- sage 背景，左上 [N.007] 与（CONTACT.），居中标题、称呼/内容两项下划线输入框、话题药丸和一个主按钮。
- 本站无后端：提交只用 mailto 生成邮件草稿，不收集、不存储数据；另提供复制邮箱。

#### 页脚

- sage 背景：居中导航（悬停翻牌）→ 超大姓名 → 所在地 → 真实社交链接 → EMAIL → 版权与返回顶部。
- 邮箱、GitHub 和社交链接必须是真实地址；返回顶部保持低调。

### 5.2 文章列表

- 全页以 ink 为主。
- 页面头部使用（POSTS.）和“文章”主标题。
- 筛选器采用描边药丸；激活项使用 sage 填充。
- 文章索引使用文字优先的两列布局，1024px 以下改为单列。
- 桌面端可以显示无障碍的 hover 预览；触屏端直接跳转。
- 移动端标题不能被序号和日期挤压：日期应移动到标题下方或摘要旁边。
- 过滤后需要保留清晰的空状态，不只显示“加载中”。

### 5.3 文章详情

文章详情是全站最克制的页面：

- 顶部保留返回文章列表、分类、日期、评论数和预计阅读时长。
- 正文宽度不超过 720px。
- 正文 17px、行高 1.85，中文段落之间保持明显呼吸。
- 代码块使用 JetBrains Mono、水平滚动和复制按钮。
- 图片宽度跟随正文，圆角 4px。
- 阅读进度条保持 2px 以内，不使用大面积动效。
- 相关内容放在正文之后，不插入阅读中段。
- 不使用字母聚拢、3D、浮动预览或全屏转场来打断阅读。

### 5.4 关于页

关于页由四个分区组成：

1. ABOUT：姓名、身份、简介、邮箱、微信、所在地和头像。
2. PATH：670px 居中时间线，显示阶段、年份、标题和说明。
3. WORKS：精选 GitHub 仓库文字索引，支持 hover/focus 弱化其他行。
4. STACK：按分类分组的纯文字技术栈。

关于页不复制 Max 的个人照片和文案。头像使用本站已有的原创资源或用户提供的正式头像。

## 6. 动效规范

### 6.1 动效等级

| 等级 | 场景 | 规则 |
|---|---|---|
| A | 加载层、字母聚拢 | 可以有明显动效，但必须可跳过 |
| B | 首屏 3D、幽灵标题、色调切换 | 低频、慢速、只使用 transform/opacity |
| C | hover、按钮、链接 | 150–300ms |
| D | 文章正文 | 默认无动效 |

### 6.2 必须保留

- Lenis 平滑滚动
- 入口加载层的字母环
- 首页关于区的字母聚拢
- 首屏 3D 主体的轻微指针/滚动响应
- 路由切换的短淡出与淡入

### 6.3 必须避免

- 多个动画同时争夺首屏焦点
- 影响布局的动画
- 超过 1.2 秒的普通入场动画
- 文章详情页中的滚动追踪装饰
- 依赖 hover 才能理解内容

### 6.4 reduced-motion

prefers-reduced-motion: reduce 时：

- 跳过加载层
- 不加载 Three.js 场景
- 幽灵标题静态显示
- 字母聚拢改为整段淡入或直接显示
- 路由直接切换
- Lenis 停止平滑滚动

## 7. 响应式与无障碍

### 7.1 断点

重点验证 375 / 768 / 1024 / 1440px。

- 375px：单列、日期下移、无浮动预览、3D 静态回退。
- 768px：允许进入桌面布局，但必须检查标题和时间线宽度。
- 1024px：文章索引可以切换为两列。
- 1440px：执行完整视觉对照。

### 7.2 无障碍底线

- 每页只有一个可见 h1。
- 装饰性幽灵标题和飞行字母使用 aria-hidden。
- 保留 sr-only 的完整正文。
- 所有按钮和链接触控区域至少 44×44px。
- 键盘可以打开、关闭和操作移动菜单。
- 当前路由有 aria-current。
- 不用低对比度装饰色承载必要信息。
- 不能只靠颜色或 hover 表达状态。

## 8. 内容与数据原则

- 内容管线保持：GitHub Issues → generate-articles.mjs → public/articles.json → 静态站点。
- 文章标题、摘要、分类和日期必须是真实内容。
- readCount 表示 Issue 评论数，不得在界面写成阅读数。
- 文章正文中的标题和代码必须使用正确 Markdown 格式。
- 文章列表不使用重复测试文章作为长期展示内容。
- 缺少封面时使用排版预览，不伪造图片。
- GitHub API 失败时使用本地精选仓库数据；不显示不可信的星标数。
- 首页“当前关注”和文章导读属于站点级编辑文案，可以在不修改文章源内容的前提下维护；它们不得冒充文章、项目成果或实时状态。
- 首页内容扩充优先采用简介、主题索引、文章摘要和明确入口，不增加虚构统计、自动轮播或重复的项目卡片。

## 9. 性能边界

- Three.js 必须动态导入，只在桌面、支持 WebGL2 且未开启省流量/减少动态效果时请求。
- 首屏回退图必须在 300ms 内可见，不等待 3D。
- 场景离开视口或页面隐藏时暂停渲染。
- 不为了隐藏构建警告而盲目放大包体预算。
- 字体继续使用 fontsource 自托管。
- 构建必须通过 tsc -b 与 vite build。

## 10. 视觉验收标准

“完成”不再等同于“能构建”或“没有横向滚动”。每次视觉改动至少检查：

1. 1440×900 与参考截图使用同一视口进行并排对照。
2. 首屏的主视觉、标题、导航和留白关系是否形成单一焦点。
3. 关于区是否有头像/视觉锚点，字母动画结束后是否完整可读。
4. 最新文章标签、编号、列表和预览是否对齐且不遮挡。
5. 375px 下标题、日期、菜单和文章正文是否完整。
6. reduced-motion 下内容是否直接可读。
7. hover、focus、触屏三种交互是否都能完成核心任务。
8. 构建、路由、资源路径和 GitHub Pages 子路径是否正常。
9. 首页“当前关注”是否在桌面保持三列对齐、在 375px 下自然转为单列，并且没有制造新的横向溢出。

以下情况不得标记为完成：

- 只有颜色相似，空间构图和视觉焦点明显不同。
- 3D 主体是黑色占位块，材质和光照不成立。
- 中文标题被截断或被装饰元素压住。
- 预览卡覆盖当前文章行。
- 文章内容仍是重复、测试或极短的占位内容。
- 只在桌面端检查，没有验证移动端和 reduced-motion。
